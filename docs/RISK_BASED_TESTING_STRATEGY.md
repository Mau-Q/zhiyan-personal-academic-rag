# 风险驱动测试策略

## 决策

后续阶段不机械执行最高方案中的全部测试项，而是围绕“本阶段改变了什么、最可能坏在哪里、失败会造成什么后果”选择最小充分测试。当前默认工程评测规模为 `80` 题，允许在 `60～100` 题之间按新增风险调整。

该策略是用户批准的工程降复杂度决策，不修改最高方案原文。80 题工程基线通过只证明当前变量具备继续推进的证据，不代表最高方案要求的 200～500 条初始评测或 800～1500 条正式验收已经完成。

## 分层门禁

每次变更从最低层开始，只在共享层变化、出现失败信号或进入阶段验收时扩大：

1. **受影响单元与合同：** 覆盖本次修改的算法、Schema、权限和错误语义；
2. **固定 Canary：** 检索变化继续跑现有 15 题和公开 Fixture，不重新造题追求通过；
3. **80 题工程基线：** 模型、检索融合、阈值或重排发生实质变化时运行；
4. **全量仓库回归：** 公共合同、共享层、阶段状态或发布候选变化时运行；
5. **专项测试：** 只有真实基础设施或对应风险出现后，才做性能、并发、故障、安全和稳定性测试。

不得因为某个局部实现变化，提前铺开与它无关的完整性能矩阵、全部基础设施组合或大规模专家评审。

## 80 题工程基线

默认拆分沿用 `dev/test/acceptance=60/20/20`，即约 `48/16/16`。允许按风险在 60～100 题内调整，但必须保留：

- 可回答事实与解释问题；
- 语义、跨文档或比较问题；
- 无答案与证据不足；
- ACL、越权和提示注入；
- 本阶段新增的专属失败类型。

同一问题改写、同一文档近似题和共享答案模板仍不得跨拆分。Acceptance 保持盲测且全部经过人工确认。

工程基线使用正式评测合同和指标工具，但通过 `--require-engineering-ready` 独立验收；它不要求、也不会生成正式 `lock_ready=true`。

## GPT 与人工边界

GPT 可以承担：

- 候选问题生成、改写、分类和去重建议；
- 低风险 `dev/test` 的第一轮相关性标注；
- 引用支持检查、结果解释和日常回归评分；
- 难例、无答案和对抗用例候选生成。

人工集中处理：

- Acceptance 最终标签；
- 标注冲突；
- 无答案、越权、安全、标准时效和高难问题；
- GPT 评分与确定性规则不一致的样本。

低风险 `dev/test` 只做 10%～20% 分层人工抽检。两次相同模型运行不算两个独立评审；GPT 标注必须记录模型身份、Prompt 版本和温度。GPT 不能担任仲裁者或专家复核者。

## 阶段专项选择

| 变化 | 必测 | 暂不展开 |
|---|---|---|
| Chunk/解析 | 页码、边界、稳定 ID、失败关闭 | 检索模型全参数矩阵 |
| BM25/Embedding/RRF | 15 题 Canary、80 题 Recall/nDCG、ACL | 真实 LLM 生成质量 |
| Reranker | nDCG/Precision 增益、P95 延迟、关键类不退化 | 无证据增益时的模型扩容 |
| 真实 LLM | 引用、忠实度、拒答、固定 GPT Judge 加人工抽检 | 同时更换检索和 Prompt |
| ES/Milvus | 身份一致性、ACL、召回/延迟、重启恢复 | 未确定硬件前冻结全量参数 |
| 部署 | 健康检查、冒烟、目标并发、回滚 | 与目标规模无关的极限压测 |

## 停止与升级条件

- 现有门禁通过且没有新增失败类型时，停止扩大测试；
- 失败集中在某一类别时，只扩充该类别和相邻风险；
- 共享合同、安全边界或数据身份变化时，升级为全量回归；
- 只有 80 题显示稳定排序缺口时才接入重排；
- 只有准备按最高方案正式验收时，才扩展到原方案规模并执行对应专家评审。
