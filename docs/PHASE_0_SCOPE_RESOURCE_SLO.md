# 方案阶段 0 范围、资源与 SLO 冻结

## 冻结结论

阶段 0 以单个已鉴权用户的个人文献库为 MVP 边界。知识来源只包括用户上传的论文，以及用户收藏后已进入其个人库的公共论文；公共库联合检索、课题组共享和跨用户检索不进入 MVP。

容量验证以 500 篇论文为标称规模、1000 篇为上界。按当前三论文 316 个 Chunk 的观测量级取整为每篇 100 个 Chunk，只用于规划 5 万/10 万 Chunk 的压测数据，不是文档切片数量上限，也不证明三篇样本能代表全部论文。

单用户流量冻结为持续 `0.2 QPS`、问答峰值并发 2、入库峰值并发 1；稳态统计窗口为 15 分钟，正式计数前执行 30 次预热请求，冷启动单独记录。混合场景至少覆盖 1 个问答与 1 个入库任务并行。该流量模型用于阶段 1 验收，不外推为平台多用户容量。

## 硬件预算

MVP 只复用一台已盘点主机，不新增硬件采购或外部 API 月度费用。相对于已确认的 i7-12700K、64 GiB 内存、RTX 4090 24 GiB 和约 400 GiB 可用数据盘，应用预算上限为 12 个物理核心、48 GiB 内存、1 张 GPU/20 GiB 显存和 300 GiB 持久化磁盘，保留主机与运行时余量。

真实生成 LLM、Reranker、平台全局分片和高可用不进入本次资源预算。它们只有在后续能力满足引入条件时单独冻结，不能从当前硬件余量推断为已部署。

## SLO 目标

| 指标 | 阶段 1 验收目标 |
|---|---:|
| 检索 P95 | `≤300 ms` |
| 检索 P99 | `≤500 ms` |
| TTFT P95 | `≤3 s` |
| 完整回答 P95 | `≤10 s` |
| 端到端 P99 | `≤15 s` |
| 超时或降级率 | `≤1%` |
| `owner_id` 范围正确率 | `100%` |
| 跨用户泄漏 | `0` |
| 引用目标/版本/页码确定性校验 | `100%` |

性能统计只接受目标主机、目标规模、固定配置和健康依赖下的可重放报告，冷启动与热态分开记录。业务 `NO_EVIDENCE`、安全拒绝和无效请求不计为服务失败，但错误的拒答或越权放行仍按质量/安全门禁失败。

## 真实性边界

本次冻结的是下一阶段的容量与验收目标，不是达标结论。现有 3 篇论文、15 题、175 题远程单路结果和三种 Chunk Baseline 只证明正确性与失败归因；尚未运行 500/1000 篇目标规模压测，真实 LLM 也未接入，因此 TTFT、完整回答延迟和成本仍处于待验证状态。

机器可读唯一值见 `machine/phase_zero_scope_resource_slo.json`。阶段 1 只有在 PostgreSQL `owner_id`/生命周期闭环和目标规模数据具备后才运行性能验收，不为关闭阶段 0 提前制造远程全量测试。
