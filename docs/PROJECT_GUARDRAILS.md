# Project Guardrails

## 范围

- 当前采用本地优先、合同优先的模块化单体；
- 本地核心与远程准备并行，远程状态不阻塞已经完成的本地链路；
- Elasticsearch、Milvus、真实模型和前端只在独立阶段逐项接入；
- 未进入 `machine/feature_list.json` 的能力不得从计划推断为已完成。

## 数据与安全

- Git 只保存源码、合同、测试、配置样例、公开 Fixture 和脱敏元数据；
- PDF、真实 Chunk、私有问题、运行报告、凭据、IP、数据库、索引和模型不得提交；
- 客户端只能收窄服务端授权范围，不能提供可信租户或 ACL 结论；
- 公开仓库前必须继续执行 `docs/REPOSITORY_POLICY.md` 的公开门禁。

## 真实性

- `FIXTURE_ONLY`、`FIXTURE_ONLY_FAKE_LLM`、`NO_EVIDENCE` 和真实外部成功必须分开；
- 本地 HTTP、真实 PDF Chunk 和远程部署分别记录，不互相替代；
- 零结果、降级、跳过或人工确认不能被改写为真实服务成功；
- Agent 自报完成不算完成，必须有测试、校验器、HTTP 结果或其他可执行证据。

## 变更控制

- 普通实现一次只改变一个主要边界；
- 破坏性合同变更必须升级版本并先确认；
- 不删除或重写用户已有工作，不把无关文件加入提交；
- 状态变化必须同时更新人类阶段文档和机器状态。
